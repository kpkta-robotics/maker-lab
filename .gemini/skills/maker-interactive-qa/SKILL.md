# Maker Interactive QA — Інспектор клікабельності та функцій сайту

Цей скіл призначений для забезпечення бездоганної роботи всіх інтерактивних елементів навчального порталу «Адаптивна цифрова майстерня». Студенти та викладачі взаємодіють із десятками кнопок, перемикачів, чекбоксів та копіювальних інструментів: жодна кнопка не має бути мертвою чи декоративною.

---

## 1. Матриця інтерактивних контрактів курсу

Кожен інтерактивний елемент сайту підпорядковується чіткому контракту даних і поведінки:

### Контракт 1: Кнопки копіювання AI-промптів та коду (`.copy-btn`)
* **Розмітка кнопки:** `<button class="copy-btn" data-target="ID_ЕЛЕМЕНТА" type="button">📋 Скопіювати промпт</button>`
* **Вимоги до цілі:** Елемент із вказаним `id` обов'язково присутній у DOM, містить непустий текст (промпт для ШІ або скетч C++).
* **Обробник:** Централізовано реалізований у `assets/lesson.js` (для уроків) та `assets/app.js` (для головної сторінки).
* **Поведінка:**
  1. Копіює чистий текст (автоматично знімає зовнішні типографські лапки `«...»`).
  2. Використовує асинхронний `navigator.clipboard.writeText()` із надійним фолбеком на прихований `textarea` та `document.execCommand("copy")` для офлайн-середовищ і безпекових контекстів.
  3. Надає миттєвий візуальний фідбек: текст змінюється на `✓ Скопійовано!`, додається клас `.copied` (зелена підсвітка) на 2000 мс.

### Контракт 2: Вбудовані інтерактивні лабораторії (`[data-lab]`, `[data-run]`)
* **Розмітка стенду:** Контейнер `.lab[data-lab="ID"]` містить:
  * `<textarea hidden data-code>` з вихідним скетчем;
  * `<button class="btn-run" data-run>` для пуску/зупинки виконання;
  * `<button class="btn-ghost" data-reset>` для повернення коду до початкового стану;
  * `<button class="btn-ghost" data-copy-lab>` для копіювання скетчу у Wokwi.
* **Перевірка:** При зміні повзунків (якщо є `data-sliders`) числа в коді мають синхронно оновлюватися. Діаграма сигналу та світлодіоди мають реагувати на зміну стану.

### Контракт 3: Вкладки рівнів складності (`#levels`)
* **Розмітка:** Кнопки з `role="tab"` та панелі з `role="tabpanel"`.
* **Зв'язок:** Атрибут `data-level="X"` кнопки обов'язково відповідає `data-panel="X"` відповідної панелі.
* **Поведінка:** Клік перемикає стан `aria-selected="true/false"` та скидає атрибут `hidden` на активній панелі.

### Контракт 4: Чек-ліст уроку та допуск до завершення (`input.check`)
* **Розмітка:** `<input type="checkbox" class="check" data-key="УНІКАЛЬНИЙ_КЛЮЧ">`
* **Обов'язкові vs Бонусні:** Бонусні пункти позначаються атрибутом `data-bonus` і не блокують завершення.
* **Поведінка:** Зміна стану автоматично зберігається у `localStorage` за ключем `arduino-course-v1:checks:УРОК:КЛЮЧ`, оновлює лічильник `#meter-text` та смужку `#meter-bar`. Кнопка `#done-btn` розблоковується лише після виконання всіх обов'язкових пунктів.

### Контракт 5: Щоденник мейкера та Exit Ticket (`#maker-artifact-box`)
* **Автогенерація:** `assets/lesson.js` автоматично монтує блок над `#lesson-footer` або `.done-row`.
* **Поведінка:**
  * Текст у `#maker-artifact-text` зберігається на льоту з індикацією «✓ Збережено».
  * Кнопка `#btn-copy-lesson-report` формує структурований звіт із контрольним хешем `KPKTA-L-XXXX` для надсилання викладачу в Telegram або Classroom.

### Контракт 6: Офлайн-синхронізація (Головна сторінка)
* `#passport-open-btn`: відкриває модальне вікно досягнень із балансом теорії та заліза ТЕКО.
* `#export-progress-btn`: вивантажує файл `[Прізвище]-maker-progress.json`.
* `#import-progress-file`: читає JSON, верифікує структуру, перезаписує `localStorage` та миттєво оновлює прогрес-бари.

## 2. Автоматизований інструмент тестування

Для перевірки всіх HTML-файлів проєкту використовується скрипт:

```bash
python scripts/test_interactive.py
```

### Що перевіряє скрипт автоматично:
1. **100% кнопок копіювання:** шукає кожну `.copy-btn`, перевіряє існування цільового `data-target` та наявність непустого тексту.
2. **Парність вкладок:** виявляє вкладки `[role="tab"]` без відповідних панелей `[role="tabpanel"]`.
3. **Чекбокси:** контролює унікальність `data-key` та наявність якоря завершення уроку (`#done-btn` або `#lesson-footer`).
4. **Внутрішні та локальні посилання:** перевіряє, чи не ведуть посилання на відсутні файли або неіснуючі id.
5. **Скрипти й стилі:** гарантує підключення `lesson.css`, `course.js` та `lesson.js` у правильному порядку.
6. **Гендерна нейтральність:** сканує інтерфейс на неприпустимі форми (`написав/написала`, `(-ла)`).

## 3. Режими роботи агента під цим скілом

### Режим 1: Швидка перевірка уроку (`verify-lesson`)
Коли створено новий урок або внесено правки в наявний:
1. Запустити `python scripts/test_interactive.py`.
2. Якщо виявлено помилки (код виходу 1) — локалізувати рядок і виправити розмітку чи скрипт.
3. Запустити `python sync_course.py` для фінального аудиту реєстрації.

### Режим 2: Додавання нової інтерактивної кнопки (`add-copy-feature`)
Коли в урок додається новий промпт або блок коду:
```html
<div class="prompt-box">
  <p id="ai-prompt-id">«Текст запиту до ШІ...»</p>
  <button class="copy-btn" data-target="ai-prompt-id" type="button">📋 Скопіювати промпт</button>
</div>
```
Завдяки централізованому обробнику в `assets/lesson.js` кнопку не потрібно оживляти власним JavaScript — вона починає працювати автоматично одразу після завантаження сторінки.

### Режим 3: Розслідування "непрацюючої кнопки" (`debug-interaction`)
1. Перевірити наявність `data-target` атрибута у `<button>`.
2. Перевірити, чи збігається `id` цільового контейнера з точністю до регістру.
3. Перевірити, чи підключено `assets/lesson.js` (або `assets/app.js`) у нижній частині сторінки перед закриваючим тегом `</body>`.
4. Перевірити, чи не перевизначає локальний скрипт уроку подію кліку через `e.stopPropagation()`.
