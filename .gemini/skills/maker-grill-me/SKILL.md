# Maker Grill-Me — Суворий Pre-Release Ревізор перед публікацією

Цей скіл реалізує методологію `/grill-me` (прискіпливий стрес-тест та узгодження рішень) спеціально для освітньої платформи **«Адаптивна цифрова майстерня: Arduino + 3D CAD + 3D Друк + AI + Maker»**.

Головне правило: **Жодна нова сторінка або суттєве оновлення не пропонується до `git push`, поки не пройдено процедуру `maker-grill-me`.**

---

## 1. Алгоритм роботи ревізора (4 кроки)

Коли користувач просить перевірити сторінку перед релізом (або перед запитом дозволу на `git push`), агент виконує:

### Крок 1: Автоматичний глибокий скан (`scripts/grill_page.py`)
Запустіть скрипт ревізії для змінених або цільових файлів:
```bash
python scripts/grill_page.py [шлях/до/файлу.html]
```
*(Якщо шлях не вказано, скрипт автоматично перевірить усі змінені файли за `git status` та базові сторінки).*

### Крок 2: Аналіз за 4 матрицями стрес-тестування

#### 🖥 Матриця А: Візуальна стійкість та CSS-цілісність (Visual & CSS Stress)
1. **Детектор мертвих CSS-класів (Dead Class Check):** Оскільки `assets/guide.css` та `assets/guide-a350.css` є прекомпільованими збірками Tailwind, будь-який новий клас у HTML (наприклад, `xl:flex`, `whitespace-nowrap`, `truncate`) **обов'язково має фізично існувати** у CSS-файлі або в локальному тезі `<style>`.
2. **Стрес-тест шапки на 360px / 900px / 1440px:**
   * Що станеться на ноутбуці з масштабом екрана Windows 125% або 150% (ефективна ширина 900–1100px)?
   * Чи захищені кнопки повернення (`← Карта курсу`, `← Діагностика`) класами `whitespace-nowrap` та `shrink-0`?
   * Чи захищений заголовок `<h1>` у фіксованій шапці (`h-14`/`h-16`) класом `truncate`?
   * Чи винесено меню з понад 5 пунктів у адаптивну смугу `.mobile-subnav` для екранів `< 1120px`?
3. **Відсутність «залиплих» активних станів:** Жоден пункт меню в `<nav>` не повинен мати захардкоджених класів активного фону (`bg-teal-50`, `bg-amber-50`) у статичному HTML.

#### ⚡ Матриця Б: Інженерна достовірність (Hardware Reality Check)
1. **Електроніка та плата ТЕКО (ATmega328P):**
   * Напруга логіки: строго `5.0 В` (або `3.3 В` для ESP32). Жодних порад подавати 9–12 В на цифрові/аналогові піни!
   * Струм піна: рекомендований `10–20 мА` (максимум 40 мА).
   * Номінали з реального набору ТЕКО: `220 Ом` (світлодіоди), `1 кОм` (транзистори/база), `10 кОм` (підтяжка кнопок / фоторезистор).
2. **3D-друк та Snapmaker 2.0 A350:**
   * Робоче поле: `320 × 350 × 330 мм`.
   * Температури PLA: сопло `200–210 °C`, стіл `60 °C`, при закритому боксі Enclosure витяжка для PLA вимкнена (щоб уникнути Warping).
   * Допуски (Clearance): отвори під гвинт M3 — `3.3–3.4 мм`, посадка під сервопривід SG90/MG90S — `+0.25..0.30 мм`.

#### 🕹 Матриця В: Інтерактивні граничні стани (Edge Cases)
1. **Калькулятори та симулятори:**
   * Що покаже калькулятор при крайніх комбінаціях (наприклад, живлення `3.3 В` + білий світлодіод `Vf = 3.2 В`)? Чи адекватний результат?
   * Чи синхронно оновлюються всі візуальні елементи (смужки на резисторі, формула, підказка, активна картка)?
2. **Тести та діагностика:**
   * Що побачить студент, якщо відповість неправильно на всі питання (0 балів) або правильно на всі (100%)? Чи чесний і корисний зворотний зв'язок?

#### 🎓 Матриця Г: Педагогіка та мовна чистота
1. **Анти-стіна тексту:** Абзаци не довші за 3–4 рядки; складні поняття пояснюються через дію або наочну картку.
2. **Мовний стандарт:** Чиста українська мова без суржику й канцеляриту, 100% гендерна нейтральність (жодних `написав/написала`, `(-ла)`, `сам/сама`, `готовий/готова`).

## 2. Формат звіту та інтерактивного допиту (Grill Session)

Після запуску `python scripts/grill_page.py` агент формує у чаті короткий **Grill-вердикт** і, якщо є неочевидні місця або дизайнерські/методичні розвилки, використовує інструмент `ask_question` (або нумерований список рішень), щоб узгодити їх із автором курсу:

```markdown
### 🔥 Grill-Me Ревізія: `[шлях до файлу]`

* **CSS та Верстка:** [OK / Знайдено N нюансів]
* **Шапка та Адаптивність:** [OK / Коментар]
* **Інженерна логіка та Edge Cases:** [OK / Коментар]
* **Мова та Педагогіка:** [OK / Коментар]

#### 🧐 Контрольні питання перед публікацією:
1. **[Питання 1 про конкретний граничний випадок або елемент сторінки]**
2. **[Питання 2 про навігацію, UX або методичний акцент]**
```

Тільки після вирішення цих питань та отримання прямого підтвердження користувача виконується `git commit` та `git push`.
