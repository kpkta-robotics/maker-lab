# AGENTS.md — Інструкція для ШІ-агентів та розробників проєкту «Адаптивна цифрова майстерня»

Цей документ є головним технічним і педагогічним стандартом освітньої платформи **«Адаптивна цифрова майстерня: Arduino + 3D CAD + 3D Друк + AI + Maker»** (250 годин) для Київського професійного коледжу «ТЕХНО-АРТ» імені Бадрі Лолашвілі (КПКТА).

Живий сайт на GitHub Pages: `https://kpkta-robotics.github.io/maker-lab/`
Локальна папка сайту: `d:\Learn Arduino\arduino-course\`

Будь-який ШІ-агент (Claude, ChatGPT, Gemini, Antigravity, Cursor тощо) або автор контенту **зобов'язаний** прочитати цей файл перед створенням чи редагуванням уроків, модулів або скриптів.

---

## 1. Мовні та стилістичні правила (СУВОРО ОБОВ'ЯЗКОВО)

1. **Виключно українська мова:** Весь інтерфейс, навчальний текст, підказки в симуляторах, коментарі в коді Arduino C++ та G-code мають бути написані грамотною, живою українською мовою без канцеляриту та суржику.
2. **Абсолютна гендерна нейтральність:**
   - **ЗАБОРОНЕНО** використовувати родові форми минулого часу при звертанні до учнівства (`ти написав`, `ти зібрала`) або конструкції з дужками/слешами (`запрограмував(-ла)`, `готовий/готова`, `сам(-а)`).
   - **ДОЗВОЛЕНО та РЕКОМЕНДОВАНО:**
     - Теперішній і майбутній час 2-ї особи однини: *«Ти створюєш», «Ти бачиш», «Ти налаштуєш», «Перевір», «Зміни параметр»*.
     - Безособові дієслівні конструкції успіху: *«У тебе вийшло запрограмувати!», «Тобі вдалося налаштувати», «Схему зібрано самостійно»*.
     - Безособові формулювання у чек-листах самоперевірки: *«Усе виконано без пропуску кроків», «Схему перевірено у Wokwi», «Знайдено та виправлено 3 помилки в профілі Luban»*.

## 2. Архітектура проєкту (Static-First для GitHub Pages)

Проєкт не потребує серверного бекенду, Node.js-збирачів чи баз даних — усе працює як чиста статика прямо з репозиторію GitHub Pages або з локальної папки `arduino-course/`:

```text
arduino-course/
├── index.html                  # Карта курсу (Hero зі схемою, прогрес, модулі, відео та джерела)
├── AGENTS.md                   # Цей стандарт для ШІ-агентів та авторів
├── sync_course.py              # Скрипт автоматичної перевірки курсу, посилань та мовних правил
├── assets/
│   ├── course.js               # ЄДИНИЙ РЕЄСТР КУРСУ: модулі, уроки, відео та корисні посилання
│   ├── app.js                  # Рендер головної сторінки, логіка прогресу та режиму викладача
│   ├── style.css               # Дизайн-система головної сторінки та класичних уроків
│   ├── lesson.css              # СПІЛЬНІ стилі інтерактивних уроків PCB (layout, toc, lab, checklist, callout…)
│   └── lesson.js               # СПІЛЬНА логіка уроків: прогрес, чек-лист, кнопка завершення, підсвічування змісту
├── _template/
│   └── lesson.html             # Базовий шаблон уроку
└── modules/
    ├── 00-diagnostic/          # Блок 0: Техніка безпеки (m0-l01), Діагностика (m0-l02), Setup IDE (m0-l03)
    ├── 01-arduino-basics/      # Модуль 1: Основи Arduino (m1-l01 .. m1-l05)
    ├── 02-3d-printing/         # Модуль 2: 3D-друк та Snapmaker A350 (m2-l01 .. m2-l06)
    ├── 03-3d-cad/              # Модуль 3: 3D CAD та моделювання (m3-l01 ..)
    └── 04-maker-project/       # Модуль 4: Командний Maker-проєкт (m4-l01 ..)
```

### Контракт збереження прогресу (`localStorage`)
Усі сторінки курсу (і головна `index.html`, і автономні інтерактивні уроки з PCB-дизайном) використовують **єдиний ключ** `localStorage`:
- Ключ прогресу: `"arduino-course-v1"`
- Формат JSON:
  ```json
  {
    "done": { "m0-l01": true, "m1-l01": true, "m2-l01": true },
    "checks": { "m1-l01:time": true, "m1-l01:sos": true, "m2-l01:zoffset": true }
  }
  ```
- Ключ режиму викладача: `"arduino-teacher"` (`"1"` — відкриває всі готові уроки незалежно від послідовності).

### Правило відносних посилань (КРИТИЧНО)
Ніколи не прописуйте жорсткі абсолютні URL `https://kpkta-robotics.github.io/maker-lab/...` всередині HTML-файлів уроків!
Завжди використовуйте **відносні шляхи**, щоб курс однаково працював і локально (`file://` або локальний сервер), і на GitHub Pages:
- З уроку (`modules/XX-name/lesson-YY.html`) на головну сторінку: `../../index.html`
- На сусідній урок у тому ж модулі: `lesson-02.html`
- На урок в іншому модулі: `../00-diagnostic/lesson-setup.html`

## 3. Дизайн-система курсу (PCB / Engineering Blueprint)

Головна сторінка (`index.html` + `assets/style.css`) та нові флагманські уроки (`modules/01-arduino-basics/lesson-01.html`, `modules/02-3d-printing/lesson-01.html`) побудовані за єдиною інженерною дизайн-системою **PCB / Engineering Blueprint**:

- **Типографіка (Google Fonts):**
  - Заголовки (`--display`): `'Unbounded'` (500/700)
  - Основний текст (`--body`): `'Golos Text'` (400/500/600/700)
  - Код і телеметрія (`--mono`): `'JetBrains Mono'` (400/600)
- **Кольорова палітра (CSS-змінні `:root`):**
  - `--paper: #F2F5F4` + `--grid: rgba(14, 102, 115, .07)` (фон креслярської міліметрівки `24px × 24px`)
  - `--surface: #FFFFFF`, `--ink: #14232B`, `--muted: #55666E`, `--line: #D3DEDB`
  - `--pcb: #0E6673` (бірюзова паяльна маска Arduino/PCB), `--pcb-deep: #0C2A31`, `--pcb-panel: #11353E` (темні панелі симуляторів і коду)
  - `--signal: #E5383B` (червоний LED / критичний акцент), `--copper: #B9761C` (мідний контакт / попередження), `--ok: #1F8A5B` (зелений індикатор успіху)
- **Макет сторінки:**
  - `.topbar` зверху з хлібними крихтами (`../../index.html`) та швидкими діями;
  - Двоколонковий `.hero` (`1.05fr 0.95fr`) із заголовком, обіцянкою результату (`.promise`), списком фактів (`.facts`) ліворуч та інтерактивною SVG-ілюстрацією плати/пристрою (`.hero-board`) праворуч;
  - Двоколонковий `.layout` (`grid-template-columns: 220px minmax(0, 1fr)`) із липким змістом `.toc` + індикатором прогресу `.meter` ліворуч та основним контентом `<main>` праворуч;
  - Інтерактивні лабораторії `.lab` на темних панелях `--pcb-deep` (від 2 до 3 симуляторів на урок).

## 4. Педагогічна структура кожного уроку (Каркас 0–8)

Кожен урок обов'язково містить послідовні секції `<section class="step" id="s1">..<section class="step" id="s8">` з навігацією у лівому змісті `.toc`:
1. **Hero + Вибір маршруту** — навіщо ця тема в реальному пристрої + зрозумілий стартовий орієнтир.
2. **Крок 01 (`#s1`): Анатомія та фізика процесу** — без перевантаження формулами, через наочні SVG-ілюстрації та інженерні картки.
3. **Крок 02 (`#s2`): Перша інтерактивна лабораторія в браузері** — миттєвий експеримент за перші 5 хвилин.
4. **Крок 03 (`#s3`): Симулятор або слайсер (Wokwi / Luban / Tinkercad)** — покроковий алгоритм дій та очікуваний результат.
5. **Крок 04 (`#s4`): Робота з реальним обладнанням (набір ТЕКО / Snapmaker A350)** — особливості підключення, техніка безпеки, передстартовий чек-ліст.
6. **Крок 05 (`#s5`): «Зламай сам» та діагностика помилок** — друга інтерактивна лабораторія з типовими багами для тренування інженерної діагностики.
7. **Крок 06–07 (`#s6`, `#s7`): Самостійний інженерний виклик + AI-ментор** — трирівневе завдання та картка `.callout.ai` із правильним промптом до ШІ (опис симптому і власної гіпотези замість «напиши за мене»).
8. **Крок 08 (`#s8`): Підсумок, чек-ліст і портфоліо** — інтерактивні чекбокси `input.check[data-key="..."]`, які оновлюють `#meter-bar` у бічній панелі та розблоковують кнопку `Позначити урок пройденим` (`#done-btn`).

## 5. Як додати новий урок, модуль або відео (Швидкий алгоритм)

### Додавання нового уроку (за 3 кроки):
1. Створіть файл уроку, наприклад `modules/02-3d-printing/lesson-02.html` (скопіювавши структуру з `modules/02-3d-printing/lesson-01.html`).
2. У новому файлі вкажіть ID уроку в `<body data-lesson="m2-l02" data-root="../../">`. Підключення спільних файлів:
   - у `<head>`: власний `<style>` лише з унікальними стилями уроку (герой-ілюстрація, симулятори), а **після нього** `<link rel="stylesheet" href="../../assets/lesson.css">` — так адаптивні `@media`-правила спільного файлу мають пріоритет;
   - перед власним скриптом: `<script src="../../assets/lesson.js"></script>`; у скрипті уроку автопозначення пункту чек-листа — `window.LessonKit.setCheck("key", true)`.
   - **Не копіюйте** в урок стилі й логіку, які вже є в `lesson.css` / `lesson.js`.
3. Відкрийте `assets/course.js`, знайдіть відповідний урок у масиві `lessons` і змініть його статус:
   ```javascript
   { id: "m2-l02", title: "Механіка міцності: периметри, заповнення та орієнтація важелів", time: "70 хв", status: "ready",
     path: "modules/02-3d-printing/lesson-02.html" }
   ```

### Додавання відео та корисних посилань на головну сторінку:
Усе редагується **в одному файлі** — `assets/course.js`:
- **Додати посилання/відео до конкретного модуля:** додайте елемент у масив `resources` всередині об'єкта модуля:
  ```javascript
  { type: "video", title: "Відео: Назва ролика", url: "https://...", tag: "Відео" }
  ```
  Підтримувані типи `type`: `"video"` (🎬), `"sim"` (⚡), `"model"` (🧊), `"tool"` (🛠), `"doc"` (📘).
- **Додати картку у глобальну бібліотеку внизу головної сторінки:** додайте елемент у масив `window.COURSE.resources`.

### Автоматична перевірка перед публікацією на GitHub Pages:
Запустіть у терміналі з папки `d:\Learn Arduino\arduino-course`:
```powershell
python sync_course.py
```
Скрипт автоматично перевірить:
- Чи всі уроки зі статусом `"ready"` у `assets/course.js` фізично існують на диску;
- Чи немає неробочих відносних посилань або випадкових абсолютних URL;
- Чи немає сирих Markdown-посилань `[текст](url.html)` усередині HTML;
- Чи збігаються ID уроків (`LESSON` / `data-lesson`);
- Чи дотримано правил гендерно-нейтральної української мови у всіх HTML-файлах (включно з минулим часом після «ти»).

## 6. Стандарт якості інтерфейсу (PCB Blueprint)

1. **Єдиний каркас уроку:** Усі уроки без винятку оформлюються за стандартом **PCB Blueprint** із підключенням `assets/lesson.css` та `assets/lesson.js`, мають бічну навігаційну панель `.toc`, індикатор прогресу `.meter` та інтерактивні стенди. Заборонено створювати уроки на застарілому одноколонковому шаблоні.
2. **Захист від сирого Markdown:** В HTML-файлах суворо заборонено залишати сирі посилання `[текст](url)` — лише валідні `<a href="...">текст</a>`.
3. **Зручність (UX):** Блоки коду та шаблони промптів для AI обов'язково забезпечуються кнопкою копіювання в 1 клік.
4. **Спільна логіка:** Спільні стилі й скрипти зберігаються лише в `assets/lesson.css` та `assets/lesson.js`.

## 7. Порядок роботи з ШІ-агентом (економія часу й токенів)

1. **Новий урок або модуль → спершу «Паспорт уроку»** (до 1 екрана): ідея Hero-ілюстрації, 2–3 лабораторії (що змінює учнівство і що бачить), практика на ТЕКО / Snapmaker A350, список зовнішніх посилань і відео з URL, пункти чек-листа. Код генерується лише після погодження паспорта — за один прохід.
2. **Дрібні правки** (текст, посилання, відео в `course.js`, кольори, виправлення помилок) → одразу в код, без паспорта.
3. **Точкові правки замість перезапису файлів.** Повністю переписувати файл можна лише тоді, коли змінюється більша його частина.
4. **Не дублювати код:** спільні стилі — у `assets/lesson.css`, спільна логіка — у `assets/lesson.js`.
5. **Одне джерело правди:** повний стандарт — лише цей файл. Кореневий `d:\Learn Arduino\AGENTS.md` містить тільки короткі правила й посилання сюди.
6. **Після змін:** `python sync_course.py`, потім перевірка в браузері (локально, до публікації на GitHub Pages).
